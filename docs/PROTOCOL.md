# 合页角度流

网页消费角度。环境光 `light` 和静置力度 `weight` 都是角度帧上的可选字段，不参与开合。轻拍是单独的 `tap` 帧。触控板轻点是网页发给桥的 `haptic`。桥负责读传感器（或造假数据）并推帧。两边的字段以本文为准：编码在 `backend/protocol.py`，解析在 `frontend/js/protocol.js`。

当前版本 **v1**。

## 传输

- WebSocket 文本帧，一条 JSON 对象。默认 `ws://127.0.0.1:19876`。
- 桥约以 `--hz`（默认 45）推角度；另约每 1 秒推一帧心跳。
- 客户端发来的角度会被忽略。只有下面这一种可选的触控板轻点会被认。
- 健康检查是另一个端口上的 HTTP，默认 WebSocket 端口 + 1（19877）：`GET /health`。

## 角度帧

```json
{"v":1,"seq":120,"t":2666.7,"type":"angle","angle":87.3,"mode":"fake"}
```

| 字段 | 含义 |
|---|---|
| `v` | 协议版本。现在是 `1`。 |
| `seq` | 本进程内单调递增的整数，从 1 起。角度和心跳共用这一条序列。 |
| `t` | 桥进程启动后的单调毫秒（`time.monotonic()`，不是墙钟）。保留 1 位小数。 |
| `type` | `"angle"`。 |
| `angle` | 度。保留 2 位小数。网页再截到 0–130。 |
| `mode` | 可选。`"fake"`、`"sensor"` 或 `"replay"`。旧桥没有这个字段。网页用它决定「自动演示」按钮：假角度默认算演示，实机合页默认跟盖子。 |
| `light` | 可选。环境光，勒克斯，保留 1 位小数。只放在角度帧上。没有传感器、这一拍读失败、或不是有限数字时，**不要这个字段**（不要写成 `null`）。`0` 是暗，不是缺失。 |
| `weight` | 可选。Force Touch 归一化静置力度，0 到 1，保留 2 位小数。**没有这个字段不是重量为零**，而是这一拍没有力度通道。`0` 才是空板。网页不把它画成秤。 |

同一帧可以同时带上这两个字段，也可以一个都不带。它们都不改 `angle`。

```json
{"v":1,"seq":120,"t":2666.7,"type":"angle","angle":87.3,"mode":"sensor","light":42.0,"weight":0.42}
```

`light` 不把过期的角度救活。网页上的开关关掉时，这个数不参与天空；开关开着但一段时间没有新的 `light`，天空回到书里的时刻。坏掉的值丢掉，不断开。

桥只在力度读数变化超过约 0.03，或距上次带上 `weight` 已有约 0.5 秒时，才写 `weight`。读不到触控板时字段整段省略，角度广播不停。

心跳不带 `light` 或 `weight`。

版本仍是 **v1**。旧网页忽略不认识的字段，旧桥不发这两个字段也仍然合法。这和可选的 `mode` 一样，不单独升版本。

同一条连接上，`seq` 不比上一帧大的消息丢掉（重放、乱序）。没有 `seq` 的帧一律收下。新连接重新计数。

对象里多出来的字段忽略，不报错。`weight` 不是有限数字时也忽略，这一帧的角度仍有效。

## 心跳

```json
{"v":1,"seq":121,"t":3666.7,"type":"heartbeat"}
```

没有 `angle`。它证明桥还活着，并占用一个序号。它**不**更新「最后一次角度」的时间：角度停了，界面仍会在 1.5 秒后变成过期，不能靠心跳假装角度还新鲜。

## 轻拍

桥在自己这边把敲击分好类，再发一条事件。网页不接收波形或采样。

```json
{"v":1,"seq":122,"t":4100.0,"type":"tap","kind":"slap","strength":0.28}
```

| 字段 | 含义 |
|---|---|
| `type` | `"tap"`。 |
| `kind` | `"slap"`、`"double-knock"` 或 `"triple-knock"`。 |
| `strength` | 力度，0 到 1，保留 3 位小数。轻拍和重拍都是 `slap`，由力度区分。 |

`seq` 和角度、心跳共用。它不更新「最后一次角度」的时间。对象里多出来的字段（包括 `waveform`、`samples`）丢掉。没有 `kind`，或 `strength` 不是有限数字：整帧丢掉。

`slap` 且力度低于网页里的 `tapStrong` 是轻拍；达到则是重拍。连敲两下、三下由 `kind` 决定，不再把原始波形交给网页。

## 旧帧

只有角度、没有 `v` / `seq` / `t` / `type` 的对象仍然有效：

```json
{"angle": 87.3}
```

解析结果记为 `v = 0`、`legacy = true`，没有序号，因此不会被序号门丢掉。`./start.sh` 拉起的桥只发 v1；这条是给已经在发旧 JSON 的小工具留的。

## 向前兼容

- 不认识的字段丢掉。没有 `weight` 的旧桥，网页当作没有力度通道。
- `type` 不是 `angle` 也不是 `heartbeat`，但带着有限的 `angle`：当成角度帧。
- `type` 为 `tap` 时按上面的轻拍帧解析；不认识的 `kind` 由网页忽略，不断开。
- 不认识的 `type` 且没有可用角度：丢掉，不断开。
- 不是 JSON、不是对象、角度不是有限数字：丢掉。

## 网页上的连接状态

`frontend/js/input.js` 用 `linkState()`（阈值 `STALE_MS = 1500`）驱动左下圆点和滑块：

| 状态 | 条件 | 界面 |
|---|---|---|
| `down` | 套接字没开 | 灰点。文案「模拟模式」。滑块可用。约 2 秒重连一次，同时只有一条连接。 |
| `wait` | 已连接，还没收到角度 | 灰点。「已连上，等待角度…」。滑块可用。 |
| `live` | 最近 1.5 秒内有角度帧 | 绿点。「传感器已连接」。滑块禁用。 |
| `stale` | 连着，但角度已超过 1.5 秒 | 黄点。「角度过期」。滑块可用。 |

心跳保持套接字，不把 `stale` 拉回 `live`。

## 网页发给桥：触控板轻点

角度仍然只从桥流向网页。网页可以另外请桥在触控板上做一下很短的轻点，用在贴纸揭开和换季落地。旧桥会把这条文本丢掉，页面不报错，这两件事照常发生。

```json
{"v":1,"type":"haptic","pattern":"tap"}
```

只认 `pattern` 为 `"tap"`（不写也当 `"tap"`）。没有力度、音量或旋钮：消息里的 `gain`、`volume`、`knob` 一律不读，轻点的长短是固定的。不是 macOS、没有触控板反馈、或系统框架不在时，桥返回不做，连接不断。

其它 `type`，以及发回桥的角度帧，继续丢掉。

## `GET /health`

`200`，`Content-Type: application/json`，`Cache-Control: no-store`。其它路径 `404`。

```json
{
  "ok": true,
  "v": 1,
  "mode": "fake",
  "clients": 1,
  "lastAngle": 87.3,
  "lastAngleAgeMs": 22,
  "seq": 120,
  "hz": 45
}
```

| 字段 | 含义 |
|---|---|
| `ok` | 进程能回答。固定 `true`。 |
| `v` | 协议版本。 |
| `mode` | `"fake"`、`"sensor"` 或 `"replay"`。 |
| `clients` | 当前 WebSocket 客户端数。 |
| `lastAngle` | 最近一次广播的角度；还没有则为 `null`。 |
| `lastAngleAgeMs` | 距那次角度的毫秒。心跳不刷新它。还没有角度则为 `null`。 |
| `seq` | 最近发出的序号（角度或心跳）。 |
| `hz` | 启动参数里的广播频率。 |

`./start.sh` 把静态页和这条健康检查都等成功，才打印地址。相同模式再执行一次时，也会看 `/health` 里有没有 `"ok": true`。
